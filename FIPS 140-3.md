# Why FIPS 140-3?

The formal FIPS 140-2 sunset took place on September 21, 2026 and it's replaced by FIPS 140-3 (valid until March 2030 as of now).

# Enable FIPS 140-3 support for Tomcat using Bouncy Castle FIPS Libraries

This page is an extension of https://github.com/amitlpande/tomcat-9-fips/blob/master/README.md which focused on FIPS 140-2 compliance for Tomcat.

For FIPS 140-3 compliance, we will need to download the BC-FIPS libraries from [bouncycastle](https://www.bouncycastle.org/download/bouncy-castle-java-fips/#latest).

Please review compatible Java versions as well as the compliance certification from NIST (https://csrc.nist.gov/projects/cryptographic-module-validation-program/certificate/4943).
https://www.bouncycastle.org/resources/bouncy-castle-crypto-api-attains-fips-140-3-certification/
For FIPS 140-3 support, we will need **bc-fips**, **bctls-fips** and **bcutil-fips** libraries.

This documentation explains steps to enforce FIPS 140-3 compliance in plain vanilla Tomcat (10.1.x) deployed on your test machine (localhost). You can skip, alter steps, binary versions as per your requirement.

# Steps

As described in https://github.com/amitlpande/tomcat-9-fips/blob/master/README.md, there are two ways you can enforce FIPS compliance in Tomcat.

1. Update JRE configuration (Can be used if your deployment uses a dedicated JRE and you don't want any programmatic support - I personally would not recommend using this.)
2. Update Tomcat instance configuration (requires configuration change + programmatic support)

Using either of these approaches some steps are commons and are outlined below.

# Commons Steps

1. Generate a X509 certificate for localhost (which will be later configured in Tomcat)
```
openssl req -x509 -out localhost.crt -keyout localhost.key \
  -newkey rsa:2048 -nodes -sha256 \
  -subj '/CN=localhost' -extensions EXT -config <( \
   printf "[dn]\nCN=localhost\n[req]\ndistinguished_name = dn\n[EXT]\nsubjectAltName=DNS:localhost\nkeyUsage=digitalSignature\nextendedKeyUsage=serverAuth")
```
You can optionally verify the certificate details using ```openssl x509 -in localhost.crt -noout -text```

2. Import into Java key store (keystore.jks):
```
  openssl pkcs12 -export -in localhost.crt -inkey localhost.key -certfile ca.crt -name myserver -out server.p12
  keytool -importkeystore -srckeystore server.p12 -srcstoretype PKCS12 -destkeystore keystore.jks
```

3. For FIPS compliance, we need to convert these JKS format keystores into BCFKS (the FIPS 140-2 and 140-3 compliant) format. You need to provide a path to the `bc-fips`
jar. So, you can update the below command as needed.
```
   keytool -providerpath bc-fips-libs/bc-fips-2.1.0.jar -providerclass org.bouncycastle.jcajce.provider.BouncyCastleFipsProvider -importkeystore -srckeystore keystore.jks
   -srcstoretype JKS -deststoretype BCFKS -destkeystore keystore.bcfks -srcstorepass ****** -deststorepass ******
```
   At this point, we have a X509 certificate for Tomcat (deployed on localhost) in the BCFKS format keystore.

4. Update the ${CATALINA_BASE}/conf/server.xml file.
   The ``SSLHostConfig`` element of the connector configuration needs to be configured to point to the BCFKS keystore:
```
        <SSLHostConfig>
            <Certificate certificateKeystoreFile="conf/keystore.bcfks"
                         certificateKeystorePassword="******" certificateKeystoreType="BCFKS"
                         certificateKeystoreProvider="BCFIPS"
            />
        </SSLHostConfig>
```

You can also tweak trust store related properties such as: truststoreFile, truststoreProvider, truststoreType if you're using a FIPS compliant trust store.
Please ensure you're using FIPS compliant cipher suites (if you don't anyways you will find that out when Tomcat reports errors when started!)

# Update JRE configuration (Not Recommended)

The steps below register the FIPS compliant security provider with the JRE.

1. Open $JAVA_HOME/conf/security/java.security file and look for
```
#
# List of providers and their preference orders (see above):
#
```
And update with below entries to register the BCFIPS provider.

```
security.provider.1=org.bouncycastle.jcajce.provider.BouncyCastleFipsProvider
security.provider.2=SunJSSE BCFIPS
security.provider.3=SUN
.
.
.
.
```
You need to renumber the entries and ensure that numbers are consecutive starting from 1. Or, you could omit other entries too.

2. Next, you need to ensure that BC-FIPS libraries are available on the classpath. In order to do that,  create the `setEnv.sh` file under `${CATALINA_HOME}/bin/` and add
```
CLASSPATH="${CLASSPATH:+$CLASSPATH:}$CATALINA_HOME/lib/bc-fips-2.1.0.jar"
CLASSPATH="$CLASSPATH:$CATALINA_HOME/lib/bctls-fips-2.1.24.jar"
CLASSPATH="$CLASSPATH:$CATALINA_HOME/lib/bcutil-fips-2.1.7.jar"
```
Save this script (ensure appropriate permissions) and exit.
Note that, I had copied the BC-FIPS libraries under  `$CATALINA_HOME/lib/` but it's not necessary, you can choose the path of your choice.

3. To run in FIPS approved mode, before starting Tomcat, you need to set a JVM property as below.
 ```
export JAVA_OPTS=-Dorg.bouncycastle.fips.approved_only=true
```
Optionally you can also add a JVM property ``-Djava.security.debug=provider`` for debugging any security provider (BCFIPS) related issues.
```
export JAVA_OPTS=-Dorg.bouncycastle.fips.approved_only=true -Djava.security.debug=provider
```
4. Now you can start Tomcat (which now runs in FIPS approved mode and any operations from within the Tomcat which are not compliant will error out!)
```
sh catalina.sh run
```
   
# Update Tomcat instance configuration
This approach doesn't need JRE modifications. And IMHO, preferred one because the FIPS configuration is localized to a specific an application (Tomcat, and all web applications deployed in the Tomcat instance). 
This also means JRE can be upgraded independently of the applications needing it.

1. Copy the BC-FIPS libraries (bc-fips-2.1.0.jar,bctls-fips-2.1.24.jar,bcutil-fips-2.1.7.jar ) to `$CATALINA_HOME/lib` to ensure that libraries are available in Tomcat's classpath.
2. In this approach, we need to implement a life cycle listener (source code below) and create a jar containing this class and put that jar under `$CATALINA_HOME/lib`

```
package com.yourorg.tomcat.listener;

import org.apache.catalina.LifecycleEvent;
import org.apache.catalina.LifecycleListener;
import org.apache.juli.logging.Log;
import org.apache.juli.logging.LogFactory;
import org.bouncycastle.jcajce.provider.BouncyCastleFipsProvider;
import org.bouncycastle.jsse.provider.BouncyCastleJsseProvider;

import javax.net.ssl.KeyManagerFactory;
import javax.net.ssl.TrustManagerFactory;
import java.security.MessageDigest;
import java.security.NoSuchAlgorithmException;
import java.security.Provider;
import java.security.Security;
import java.util.logging.Logger;

/**
 * This lifecycle listener registers security provider from Bouncy Castle FIPS.
 */
public class BCFIPSProviderRegistrationLifecycleListener implements LifecycleListener {

    private static final Log LOG = LogFactory.getLog(BCFIPSProviderRegistrationLifecycleListener.class);

    //C:HYBRID sets how the DRBG is seeded
    //
    //This controls the entropy source behind BCFIPS’s random number generator.
    // In HYBRID mode, a background thread (“BC FIPS Entropy Daemon”)
    // keeps a pool of pre-collected entropy ready, so foreground operations rarely have to wait.
    // Without it, BCFIPS gathers entropy on demand. On servers, especially VMs and containers with little entropy,
    // that can make SecureRandom calls, key generation, and TLS handshakes stall.
    // So HYBRID is mainly a startup and latency fix for server workloads like Tomcat.
    // You’ll see a thread with that name in thread dumps when it’s active.

    // ENABLE{All} enables optional services

    // The command ;ENABLE{All} serves as a direct instruction to fully activate, unlock, or
    // engage all available modules, features, or operational capabilities within the current context.

    private static final String FIPS_CONFIG = "C:HYBRID;ENABLE{All};" ;

    static {

        boolean fipsMode = false;

        String strFipsModeSystemProperty = System.getProperty("com.safelogic.cryptocomply.fips.approved_only");
        if (strFipsModeSystemProperty != null && !strFipsModeSystemProperty.isEmpty()) {
            fipsMode = "true".equalsIgnoreCase(strFipsModeSystemProperty);
        }

        /*
         * First add the Bouncy Castle Fips security provider
         */
        Provider bouncyCastleFipsProvider = new BouncyCastleFipsProvider(FIPS_CONFIG);

        Security.insertProviderAt(bouncyCastleFipsProvider, 1);

        if (fipsMode) {

            LOG.debug("FIPS mode enforced. Reconfiguring SunJSSE.");
            //If your application runs in FIPS mode using BouncyCastleFipsProvider, you must use the corresponding Bouncy Castle JSSE provider
            //Why: The standard JDK JSSE provider (SunJSSE) relies on default JVM or platform cryptographic primitives that may not be
            //FIPS-validated. Pairing BCFIPS with BCJSSE ensures that every stage of the TLS handshake, key exchange,
            // certificate validation, and bulk data encryption uses FIPS-approved algorithms and operational modes.
            //fips:: Tells the provider to initialize in FIPS-enforced mode,
            // ensuring that all TLS handshakes and cryptographic operations adhere strictly to approved standards.
            //BCFIPS: Specifies the registered name of the underlying BouncyCastleFipsProvider instance that the JSSE layer
            //will use for its cryptographic primitives.
            Security.insertProviderAt(new BouncyCastleJsseProvider("fips:BCFIPS"), 2);
            Security.removeProvider("SunJSSE");
            Security.setProperty("ssl.TrustManagerFactory.algorithm", "PKIX");
            Security.setProperty("ssl.KeyManagerFactory.algorithm", "PKIX");
            LOG.debug("ssl.KeyManagerFactory.algorithm = " + KeyManagerFactory.getDefaultAlgorithm());
            LOG.debug("ssl.TrustManagerFactory.algorithm = " + TrustManagerFactory.getDefaultAlgorithm());
        }
        Provider[] providers = Security.getProviders();

        if (providers != null && providers.length > 0) {

            for (int i = 0; i < providers.length; i++) {

                LOG.info("Added provider: " + providers[i].getName() + " Info: " + providers[i].getInfo());
            }
        }

        //Log a verification message that will confirm if the Tomcat is running in FIPS approved only mode or not.
        try {
            MessageDigest.getInstance("TIGER");
            LOG.info("Tomcat is running in non-FIPS mode.");
        } catch (NoSuchAlgorithmException e) {
            LOG.info("Tomcat is running in FIPS mode.");
        }
    }

    @Override
    public void lifecycleEvent(LifecycleEvent lifecycleEvent) {
    }
}

```

3. Now, we need to register this listener with Tomcat by adding it in the server.xml.

```
   <Server port="8005" shutdown="SHUTDOWN">
   <Listener className="org.apache.catalina.startup.VersionLoggerListener" />
  <Listener className="com.yourorg.tomcat.listener.BCFIPSProviderRegistrationLifecycleListener" /> <!-- Register it as early as possible in the sequence -->
    <!-- Security listener. Documentation at /docs/config/listeners.html
  <Listener className="org.apache.catalina.security.SecurityListener" />
  -->
```

4. To run in FIPS approved mode, before starting Tomcat, you need to set a JVM property as below.
```
export JAVA_OPTS=-Dorg.bouncycastle.fips.approved_only=true
```
Optionally you can also add a JVM property ``-Djava.security.debug=provider`` for debugging any security provider (BCFIPS) related issues.
```
export JAVA_OPTS=-Dorg.bouncycastle.fips.approved_only=true -Djava.security.debug=provider
```
5. Now you can start Tomcat (which now runs in FIPS approved mode and any operations from within the Tomcat which are not compliant will error out!)
```
sh catalina.sh run
```
You can see below log lines to confirm if Tomcat is running in FIPS approved mode or not.
